# 스토어 출시 그래픽 에셋

Google Play Console 등록에 필요한 그래픽(앱 아이콘 · 대표 그래픽 · 휴대전화 · 태블릿 스크린샷)을 **처음부터 끝까지** 만드는 절차입니다.
"스토어 에셋 만들어줘", "출시용 스크린샷 · 아이콘" 같은 요청을 받으면 이 문서대로 진행합니다.

- 중간에 사용자에게 묻지 않습니다. 판단이 필요한 것은 직접 정하고, **마지막에 무엇을 왜 그렇게 정했는지** 알립니다.
- 프로젝트 전용 값(스크립트 위치, 샘플 데이터, 고른 화면)은 `store-assets/README.md`에 둡니다. 이미 있으면 그것부터 읽고, 스크립트를 다시 돌리는 것으로 끝나는지 먼저 확인합니다.

## 0. 입력

요청에 없으면 코드 · 문서에서 파악해 정합니다.

| 항목 | 비어 있을 때 |
|---|---|
| 앱 한 줄 설명 | 제품 문서 · 스토어 설명 · `strings.xml`에서 |
| 스크린샷 문구 언어 | 앱 UI 언어 (기본 한국어) |
| 분위기 · 색상 | 앱 테마 토큰 |
| 꼭 보여줄 화면 | 1장 기준으로 직접 고름 |

## 1. 프로젝트 파악

- 프레임워크(Compose / XML View / Flutter / React Native 등), 앱 이름, 패키지명(flavor 접미사 포함), 테마 색, 글꼴, 기존 런처 아이콘, 주요 화면과 이동 경로를 코드에서 확인합니다.
- **핵심 가치를 가장 잘 보여주는 화면 4~6개**를 고릅니다. 로그인 · 설정 · 빈 화면은 빼고, 입력 칸이 비어 보이는 편집 화면도 피합니다.
- 앱의 사용 방식이 여럿이면(예: 혼자 쓰기 / 함께 쓰기, 무료 / 구독) 각각이 한 장 이상 보이게 고릅니다.
- 다크 모드 · 테마 · 위젯처럼 화면 밖 기능은 실제로 찍을 수 있을 때만 넣습니다.

## 2. 실제 앱 화면 캡처

**화면은 반드시 실제 앱에서 캡처한 것만** 씁니다. 없는 기능을 그려 넣지 않습니다.

### 기기

- 에뮬레이터 3종: 휴대폰, 7인치 태블릿, 10인치 태블릿. 모두 **세로**.
- 시스템 이미지는 `google_apis`(Play 스토어 없는 것): `adb root`가 되고 Play 서비스가 들어 있습니다.
- 10인치(Nexus 10)는 가로가 기본이라 `hw.lcd.width/height`를 바꿔 세로 기기로 만듭니다.
- 창 없이(`-no-window`), 매번 `-wipe-data`로 띄우고 포트를 고정해 다른 에뮬레이터와 겹치지 않게 합니다.

### 이동 · 데이터 준비는 스크립트로

- 화면 이동은 다시 돌릴 수 있게 스크립트로 만듭니다 (UI 테스트, Maestro, 안 되면 `adb` 입력 + `uiautomator dump`로 글자를 찾아 누르기).
- 샘플 데이터는 자연스럽게, **실제 개인정보 없이** 넣습니다. 프로젝트 문서에 샘플 시나리오가 있으면 그것을 씁니다.
- 로그인이 필요한 앱:
  - 실제 계정 대신 백엔드 에뮬레이터(예: Firebase Auth · Firestore 에뮬레이터)에 연결되는 빌드를 씁니다.
  - 로그인 · 데이터 넣기는 **앱의 계측 테스트**(androidTest)가 앱의 실제 저장소 API로 합니다. DB 파일을 직접 고치는 것보다 앱 규칙과 어긋나지 않습니다. 평소 테스트에서는 건너뛰게 인자가 없으면 바로 끝냅니다.
  - Firebase Auth 에뮬레이터는 서명 없는 JSON(`{"sub":…,"email":…}`)을 Google ID 토큰으로 받습니다. **같은 이메일은 같은 계정으로 묶이므로** 기기마다 다른 이메일을 씁니다.
  - 상대방이 필요한 기능(공유 · 연결)은 같은 테스트 안에서 별도 `FirebaseApp` 인스턴스로 상대 기기를 흉내 냅니다.
  - 실행마다 에뮬레이터 데이터를 지워 지난 실행의 데이터가 쌓이지 않게 합니다.
- 기기 날짜를 샘플 시나리오의 "오늘"로 바꾸면, 서버 시각과 비교하는 보안 규칙(만료 시각 등)이 실패할 수 있습니다. **데이터는 실제 시각으로 넣고, 캡처 직전에 날짜를 옮깁니다.**

### 캡처 전에 정리

- 상태바: 시스템 UI 데모 모드로 시계 12:00, 배터리 100%, 알림 아이콘 없음. System UI가 다시 시작되면 풀리므로 **캡처할 때마다 다시 켭니다.**
- 애니메이션 끄기, 소프트 키보드 끄기(IME 비활성), 잠금 화면 해제, 시간대 고정.
- 디버그 배너 · 개발용 버튼 · 키보드 · 로딩 중 상태가 찍히지 않게, 기다릴 글자(`wait_for`)를 정해 그려진 뒤 찍습니다.
- 태블릿은 앱 화면 아래에 런처 작업 표시줄(다른 앱 아이콘)이 나옵니다. 앱을 찍는 동안 런처를 끕니다 (`pm disable-user`, 끝나면 `pm enable`). 이때 뜨는 "System UI keeps stopping" 창은 닫습니다.
- 홈 화면 위젯을 찍으려면 런처가 켜져 있어야 하고(앱이 고정 요청 지원 여부를 보고 버튼을 숨길 수 있음), 화면에 다른 앱 아이콘 · 브랜드가 함께 찍힙니다. 독은 합성할 때 화면 밖으로 밀어내고, 런처에 자리가 없는 기기는 위젯 장을 뺍니다.
- 캡처: `adb exec-out screencap -p`. 합성 전 원본은 `store-assets/raw/{phone,tablet-7,tablet-10}/`에 둡니다.

## 3. 스토어용 스크린샷 합성

- 캡처 이미지에 배경 · 짧은 문구(화면당 한 줄, 12자 안팎) · 기기 프레임을 얹습니다. HTML/CSS를 헤드리스 브라우저로 렌더링하거나 Python(Pillow)을 씁니다.
- 색 · 글꼴은 앱 테마에서 가져오고(토큰 파일 · 앱에 든 글꼴 파일을 직접 읽어 어긋나지 않게), 전체 장을 한 세트로 통일합니다.
- 문구는 **기능이 아니라 사용자가 얻는 것**을 씁니다. "1위", "최고", "무료", 가격, 순위, 수상 내역, 다른 앱 · 브랜드 이름은 넣지 않습니다.
- 사용 방식을 구분하는 장(예: 혼자 쓸 때 / 둘이 쓸 때)은 문구 위에 작은 라벨을 붙일 수 있습니다.
- 태블릿용은 **휴대폰 캡처를 늘리지 말고** 태블릿 에뮬레이터에서 찍은 것을 씁니다.

| 종류 | 크기 | 장수 |
|---|---|---|
| 휴대폰 | 1080x1920 | 4~6 |
| 7인치 태블릿 | 1440x2560 | 4 이상 |
| 10인치 태블릿 | 1800x3200 | 4 이상 |

모두 9:16 세로, 알파 없는 24비트 PNG 또는 JPEG, 장당 8MB 이하.

## 4. 앱 아이콘 (512x512)

- 런처 아이콘이 이미 제대로 있으면 그것을 기준으로 512 버전을 만듭니다 (적응형 아이콘이면 foreground + background 합성).
- 아이콘이 없거나, 기본 안드로이드 아이콘이거나, 앱 성격과 맞지 않으면(예: 한 사용 방식만 떠올리게 함, 글자가 들어 있음) SVG로 새로 디자인합니다.
  - 앱의 핵심을 나타내는 단순한 심볼 하나, 색 2~3개, **글자 없음**, 48px에서도 알아볼 수 있게.
  - 서로 다른 방향으로 **시안 3개**를 만들고 하나를 추천해 최종본으로 정합니다. 비교 시트(Play 모양 · 런처 원형 · 48px)를 함께 만듭니다.
  - 심볼은 108x108 좌표의 path로 정의해 SVG와 Android 벡터 드로어블에 함께 씁니다. 런처 안전 영역(가운데 지름 66) 안에 둡니다.
  - Play 아이콘은 가장자리까지 보이고 런처는 가운데 약 72만 보이므로, 512 아이콘은 가운데 80x80을 잘라 써서 두 곳에서 심볼 크기가 비슷하게 보이게 합니다.
- 규격: 512x512, 32비트 PNG(알파 포함), 1024KB 이하. 모서리 둥글림 · 그림자는 Play가 넣으니 **꽉 찬 정사각형**.
- 새로 디자인했으면 앱의 적응형 아이콘 리소스(`mipmap-anydpi-v26` + 단색 테마 아이콘 + 해상도별 PNG)도 같은 디자인으로 만들어 `store-assets/icon/android-res/`에 둡니다. **기존 앱 리소스는 덮어쓰지 않습니다** (사용자가 적용을 요청할 때만, 이전 파일을 지우고 바꿈).

## 5. 대표 그래픽 (1024x500)

- 아이콘 심볼 + 앱 이름 + 한 줄 문구. 아이콘 · 스크린샷과 같은 색 체계.
- 중요한 내용은 **가운데**에 모으고 가장자리에는 장식만 둡니다 (잘리거나 재생 버튼이 겹칠 수 있음).
- 규격: 정확히 1024x500, 알파 없는 24비트 PNG 또는 JPEG.

## 6. 검증과 정리

- 검증 스크립트로 모든 파일의 크기 · 포맷 · 알파 유무 · 용량 · 장수를 확인하고 표로 출력합니다. 하나라도 어긋나면 실패로 끝냅니다.
- 완성본을 직접 열어 보고 글자 잘림, 겹침, 낮은 대비, 깨진 한글 글꼴, 찍히면 안 되는 것(다른 앱 아이콘, 디버그 표시, 실제 시각 상태바)이 있으면 고칩니다.
- 결과물 구조:

  ```
  store-assets/
    icon/icon-512.png            (+ 시안 icon/options/, 앱 리소스 icon/android-res/)
    feature-graphic/feature-1024x500.png
    screenshots/phone/01.png ...
    screenshots/tablet-7/01.png ...
    screenshots/tablet-10/01.png ...
    raw/                         합성 전 원본 캡처
    README.md                    각 파일을 Play Console 어느 칸에 올리는지, 다시 생성하는 명령
  ```

- 전체를 한 번에 다시 돌리는 스크립트를 `tools/store-assets/`에 남깁니다 (`run_all.sh` 전체, `run_all.sh compose` 캡처 없이 합성만).
  가상환경 · 로그는 `.gitignore`에 넣습니다.
- 앱 소스 코드는 캡처에 꼭 필요한 경우(예: 샘플 데이터용 계측 테스트)가 아니면 건드리지 않고, **커밋하지 않습니다.**

## 막히면

- 에뮬레이터를 띄울 수 없는 환경이면 **멈추고** 이유와 사용자가 해야 할 일을 알립니다. 가짜 화면을 그려서 대체하지 않습니다.
- 비밀 파일(`google-services.json` 등)이 없어 빌드가 안 되면 무엇이 필요한지 알립니다.
