# 광고 전략

> **2026-11 결정 (현재 범위):** 광고는 **보상형 광고 두 곳, "사진 1장 더"와 "백업하기"**만 넣습니다 (6장). 저장할 때마다 보여주는 광고는 넣지 않습니다. 전면광고 · 다른 보상(테마 · 위젯 해금) · 광고 제거 구매는 넣지 않고, 광고 제거 대신 **혜택 없는 후원(개발자 응원하기)**을 둡니다 (6장). 2 · 3장은 처음 검토한 내용으로, 다시 넣을 때 참고합니다.

## 1. 기본 방향

- **배너 광고는 사용하지 않습니다.** 화면 완성도를 해치기 때문입니다.
- 아이디어의 출발점인 "서버 자원을 많이 쓰는 행동에 광고를 연결한다"는 합리적입니다. 다만 **강제로 보여주는 전면광고보다, 사용자가 선택하는 보상형 광고**로 연결하는 것이 사용자 경험과 정책 양쪽에서 안전합니다.
- ~~광고 수익과 함께 광고 제거 1회 구매를 제공합니다.~~ → 광고가 사용자가 고르는 보상형 하나뿐이라 지울 광고가 없습니다. 후원으로 바꿨습니다 (6장).

## 2. 제안된 시점별 판단

| 시점 | 판단 | 이유 |
|---|---|---|
| 커플 연결 직후 전면광고 | ❌ 비추천 | 앱에서 가장 감정적인 순간이고 대부분 설치 첫날입니다. 여기서 흐름이 끊기면 초반 이탈이 커집니다. |
| 자동 동기화 시 | ❌ 불가 | 사용자 행동이 아니라 광고를 띄울 자연스러운 시점이 없습니다. 예고 없이 뜨는 전면광고는 정책 위반 위험이 있습니다. |
| 이미지 업로드마다 전면광고 | ⚠️ 조건부 | 매번 띄우면 거부감과 정책 위험이 함께 커집니다. |
| 이미지 업로드를 **보상형 광고**로 | ✅ 추천 | "무료 N장, 광고 보면 1장 추가". 비용과 직접 연결되고 사용자가 스스로 선택합니다. |
| 디데이 · 일정 저장 후 홈 복귀 시 전면광고 | ✅ 빈도 제한 조건부 추천 | 작업이 끝난 자연스러운 화면 전환 지점입니다. |
| 앱 실행 시 (앱 오프닝 광고 포함) | ❌ 비추천 | 디데이 앱은 짧게 열고 닫는 앱이라 진입 광고의 거부감이 큽니다. 위젯 위주 사용자에게 특히 불리합니다. |

## 3. 추천 조합

### 보상형 광고 (주력)

| 보상 | 설명 |
|---|---|
| 사진 업로드 1장 추가 | 무료 한도를 넘었을 때 |
| 테마 해금 | 핑크 외 테마를 광고 시청으로 해금 (영구 또는 기간제) |
| 위젯 스타일 해금 | 사진 배경 위젯, 중간 크기 위젯 등 |
| 디데이 공유 이미지 고급 템플릿 | "이미지로 공유" 기능의 추가 디자인 |

- 보상 내용을 버튼에 명확히 적습니다. 예: "광고 보고 사진 1장 더 올리기"
- 광고 로드 실패 시에도 보상을 주거나 다시 시도할 수 있게 해서 사용자가 손해 보지 않게 합니다.

### 전면광고 (보조)

| 규칙 | 값 |
|---|---|
| 노출 시점 | 디데이 · 일정 저장 완료 → 홈으로 돌아갈 때 |
| 하루 최대 노출 | 1~2회 |
| 최소 간격 | 직전 노출 후 3분 이상, 사용자 행동 2회 이상 |
| 신규 사용자 보호 | 설치 후 3일간 미노출 |
| 미노출 상황 | 커플 연결 직후, 온보딩 중, 앱 실행 · 종료 시점, 다른 광고 직후 |

- 광고는 미리 로드해 두고, 준비되지 않았으면 그냥 건너뜁니다. 로딩을 기다리게 하지 않습니다.
- AdMob 콘솔에서 **건너뛸 수 없는 동영상 전면광고를 끄는 것**을 권장합니다.

### 광고 제거 1회 구매

- 커플 앱에서는 광고보다 이 수익 비중이 더 클 수 있습니다.
- **커플 중 한 명이 구매하면 두 사람 모두 광고가 제거되는 옵션**은 강한 판매 포인트입니다. 구매 정보는 `couples` 문서에 플래그로 두고, 구매 검증은 Google Play 결제 검증으로 처리합니다.
- 보상형 광고로 해금하던 테마 · 위젯은 구매 시 전부 해금합니다.

## 4. AdMob 정책 체크리스트

- 전면광고는 앱 안의 자연스러운 중단 · 전환 지점에만 배치합니다.
- 앱을 열 때, 종료할 때 전면광고를 띄우지 않습니다.
- 사용자 행동 2회당 전면광고 최대 1회. 뒤로 가기 버튼도 행동으로 셉니다.
- 광고를 닫자마자 다른 광고를 띄우지 않습니다.
- 앱 오프닝 광고를 쓴다면 다른 광고 직전 · 직후에 표시하지 않습니다.
- 위반 시 앱의 광고 게재가 중단될 수 있습니다.

## 5. 구현 메모

- 광고 노출 기록(마지막 노출 시각, 오늘 노출 수, 설치일)은 DataStore에 저장합니다.
- 노출 규칙은 Firebase Remote Config(무료)로 원격 조정하면, 앱 업데이트 없이 빈도를 바꿀 수 있습니다.
- 광고 정책 · 동의(UMP, 맞춤 광고 동의)는 설정의 "개인정보 처리방침" 및 약관 동의 흐름과 함께 검토합니다.

## 6. 현재 구현 (2026-11)

### 보상형 광고: 사진 1장 더

| 항목 | 값 |
|---|---|
| 나오는 곳 | 커플 프로필 사진 · 공유 항목 커버 사진을 고를 때, 커플 누적 한도를 다 썼으면 시트 "광고 보고 사진 1장 더 올리기" |
| 보상 | 커플 사진 한도 +1 (최대 +30). 두 사람이 함께 씀 |
| 확인 | AdMob 서버 측 확인(SSV) → `admobReward` 함수가 서명을 확인하고 `usage/images.bonus` +1 (`infra-and-billing-protection.md` 2-5). 앱은 bonus가 오를 때까지 최대 20초 기다렸다가 사진 선택기를 연다 |
| 불러오기 | 버튼을 누를 때 불러와 바로 보여줌 (미리 불러 두지 않음). 실패하면 "광고를 불러오지 못했어요" |
| 동의 | 맞춤 광고 동의(UMP)를 광고를 처음 띄울 때 확인. 동의가 필요한 지역(EEA · 영국 등)만 화면이 뜬다 |

- 광고를 중간에 닫으면 보상 없이 시트에 남습니다. 보상이 20초 안에 반영되지 않으면 "잠시 후 다시"로 알리고, 다시 사진을 누르면 한도를 새로 읽으므로 늦게 반영된 보상도 그대로 씁니다.
- 커버 사진은 우리 둘이 디데이에만 넣을 수 있습니다 (나만 보기 · 솔로 항목은 사진 칸 없음). 솔로 프로필 사진은 서버에 올리지 않으니 한도를 묻지 않습니다.

### 보상형 광고: 백업하기

| 항목 | 값 |
|---|---|
| 나오는 곳 | 설정 → 백업 · 복원 → "광고 보고 백업하기" |
| 보상 | 백업 1번 (복원에는 광고 없음) |
| 확인 | 앱에서만 (`onUserEarnedReward`). 서버 측 확인 값을 넣지 않는다: 백업 남용은 Storage 규칙(본인만 · 2MB · 10분 간격)이 막기 때문. 같은 광고 단위라 AdMob 콜백은 오지만 `admobReward`가 값이 없어 무시한다 (함수 호출 1번) |
| 실패 | 광고를 불러오지 못하면 광고 없이 백업 (데이터를 잃지 않게). 중간에 닫으면 백업하지 않음 |

### 후원 (개발자 응원하기)

- 설정 → 지원 → "개발자 응원하기": 소모형 인앱 상품 3종, 혜택 없음. Play Billing만 쓰고 서버 검증은 하지 않습니다 (주는 것이 없음).

  | 상품 id (Play Console) | 앱 표시 | 가격 |
  |---|---|---|
  | `support_small` | 따뜻한 응원 | ₩1,200 |
  | `support_medium` | 달콤한 응원 | ₩3,300 |
  | `support_large` | 든든한 응원 | ₩6,600 |

- 가격은 Play Console 값을 그대로 보여줍니다 (사용자 통화). 상품이 등록되지 않았거나 Play에 연결하지 못하면 "사용할 수 없어요"를 보여줍니다.
- 결제되면 바로 소모합니다(같은 상품을 다시 살 수 있게, 3일 안에 소모하지 않으면 Play가 환불). 결제 중 앱이 종료되거나 보류됐다가 결제된 구매는 화면을 다시 열 때 소모합니다.
- 자선 단체 기부가 아니라 개발자에게 주는 팁이라 Play 결제로 받습니다. "기부"라는 표현은 쓰지 않습니다.
