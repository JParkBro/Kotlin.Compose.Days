# 제품 · 화면 정의

데이즈(Days)의 기능 범위, 데이터 규칙, 화면 목록과 동작을 정의합니다. 디자인 시안(Stitch) 작업과 개발 모두 이 문서를 기준으로 합니다.

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | 혼자 쓰는 디데이도, 둘이 쓰는 기념일도 한 곳에서 |
| 대상 | 20~30대 한국 사용자 (커플 및 개인) |
| 플랫폼 | Android (iOS는 이후 검토) |
| 앱 표시 이름 | 두 사람의 날들 (가칭) |
| 기본 원칙 | 솔로 모드가 기본이고, 커플 연결은 그 위에 얹는 기능 |

### 사용 모드

| 모드 | 설명 |
|---|---|
| 솔로 | 로그인 후 바로 개인 디데이 · 일정 사용. 모든 항목은 "나만 보기" |
| 커플 | 커플 코드로 상대와 연결. 항목별로 "우리 둘이"(공유) 또는 "나만 보기" 선택 |

---

## 2. 항목(Item) 규칙

### 2-1. 항목 종류

| 구분 | 디데이 (DDAY) | 일정 (PLAN) | 자동 기념일 |
|---|---|---|---|
| 목적 | 날짜를 세기 | 약속 · 할 일 | 사귄 날 · 생일에서 파생 |
| 필수 입력 | 제목, 기준일 | 제목 | 없음 (저장하지 않고 계산) |
| 선택 입력 | 계산 방식, 1일 세기, 반복, 알림, 공개 범위, 카테고리, 색 · 배경, 대표 고정, 메모 | 날짜, 시간, 장소, 메모, 공개 범위, 알림, 디데이로 세기 | 개별 숨김만 가능 |
| 지난 뒤 | D+로 계속 셈 | 캘린더에만 남음, 완료 체크 가능 | 흐리게 표시 |

### 2-2. 계산 규칙

| 규칙 | 내용 |
|---|---|
| 계산 방식 | `D-Day`(남은 날 카운트다운) / `D+`(지난 날 카운트) |
| 시작일을 1일로 세기 | **D+ 모드에서만** 노출. 켜면 기준일 당일이 1일 (한국식 커플 디데이) |
| 반복 | 없음 / 매년 / 매월. 반복 항목은 다음 도래일 기준으로 D-day 계산 |
| 당일 | `D-Day`로 표시 |
| 임박 | 7일 이내는 위험 색(danger)으로 강조 |
| 지난 디데이 | D-Day 방식에서 기준일이 지나면 D+로 계속 셈 (1일 세기 미적용) |
| D+ 방식의 미래 기준일 | 기준일 전에는 D-N으로 남은 날을 표시하고, 당일부터 D+로 셈 |
| D+ 방식의 당일 | 1일 세기를 켜면 D+1, 끄면 D-Day |
| 반복 · 2월 29일 | 매년 반복 · 생일이 2월 29일이면 평년에는 2월 28일 |
| 반복 · 월말 | 매월 반복 날짜가 없는 달(예: 31일 → 4월)은 그 달 말일. 다음 달은 원래 날짜로 돌아감 |

### 2-3. 자동 기념일

| 종류 | 생성 규칙 | 숨김 키 |
|---|---|---|
| 100일 단위 | 사귄 날 기준 100, 200, 300 … 일 | `DAY_{n}` |
| 주년 | 사귄 날 기준 매년 | `YEAR_{n}` |
| 생일 | 두 사람 프로필의 생일, 매년 | `BDAY_{uid}_{연도}` |

자동 기념일은 저장하지 않고 기기에서 계산하며, 사용자가 숨긴 것만 저장합니다.

### 2-4. 일정 시간 입력

| 선택지 | 저장 값 |
|---|---|
| 종일 | `ALL_DAY` |
| 아침 · 점심 · 저녁 | `MORNING` · `LUNCH` · `EVENING` |
| 시간 지정 | `EXACT` + `HH:mm` |

"디데이로 세기"를 켠 일정은 홈 리스트와 위젯에 D-day로 표시됩니다 (예: 여행).

### 2-5. 카테고리

기념일 / 생일 / 여행 / 시험·목표 / 일상 / 기타

### 2-6. 공개 범위

| 값 | 의미 | 노출 조건 |
|---|---|---|
| 나만 보기 (PRIVATE) | 내 기기에만 저장, 서버에 올리지 않음 | 항상 |
| 우리 둘이 (SHARED) | 커플 상대와 공유, 양쪽 모두 수정 가능 | 커플 연결 시에만 |

**사용자별 설정 (공유되지 않음):** 홈 대표 고정, 알림 설정. 같은 공유 디데이라도 사람마다 다르게 정합니다.

## 3. 화면 구조

### 3-1. 내비게이션

하단 탭 3개: **홈 / 캘린더 / 설정**

```
온보딩
 ├─ 소개 → 로그인 → 약관 동의 → 시작 방식 선택
 │                                 ├─ 혼자 시작 → 홈(솔로)
 │                                 └─ 커플 연결 → 커플 연결 흐름 → 홈(커플)

메인 탭
 ├─ 홈 ─────┬─ 디데이 상세 ─ 디데이 수정
 │          ├─ + 선택 시트 ─ 디데이 추가 / 일정 추가
 │          └─ 알림 목록
 ├─ 캘린더 ─┬─ 날짜 선택 상태
 │          ├─ 항목 상세
 │          └─ 일정 추가 (선택한 날짜 미리 채움)
 └─ 설정 ───┬─ 프로필 수정
            ├─ 커플 관리 ─ 연결 해제 시트
            ├─ 테마 시트, 알림 설정, 위젯 설정
            ├─ 공지사항, 문의하기
            ├─ 약관 및 정책 ─ 정책 문서 보기, 오픈소스 라이선스
            └─ 계정 관리 ─ 회원 탈퇴 확인
```

### 3-2. 화면 목록

| 그룹 | 화면 | 비고 |
|---|---|---|
| 온보딩 | 소개 | 2~3장 스와이프 |
| | 로그인 | 카카오 · Google. 비로그인 사용 없음 |
| | 약관 동의 | 아래 5장 참고 |
| | 시작 방식 선택 | 혼자 / 커플. 나중에 변경 가능 |
| 커플 연결 | 내 코드 | 24시간 유효, 복사 · 카카오톡 공유 · QR |
| | 코드 입력 | 6자리, 시스템 키보드 |
| | 연결 확인 | 상대 확인, 사귄 날 설정, 1일 세기 |
| 홈 | 홈 (커플 / 솔로 / 빈 상태) | 4장 참고 |
| | + 선택 시트 | 디데이 / 일정 |
| | 알림 목록 | 상대 활동, 기념일 알림 |
| 항목 | 디데이 상세 | 배경 사진, 다가오는 기념일 타임라인, 메모 |
| | 디데이 추가 · 수정 | 같은 화면 재사용 |
| | 일정 추가 · 수정 | 가벼운 입력 |
| 캘린더 | 캘린더 탭 | 월 그리드 + 리스트 |
| 설정 | 설정 탭 | 6장 참고 |
| | 프로필 수정, 커플 관리, 알림 설정, 위젯 설정, 계정 관리 | |
| | 테마 시트, 연결 해제 시트 | 바텀시트 |
| | 약관 및 정책, 정책 문서 보기, 오픈소스 라이선스 | 오픈소스 라이선스는 oss-licenses 플러그인 화면(`OssLicensesMenuActivity`) |
| | 회원 탈퇴 확인 | |

## 4. 주요 화면 동작

### 4-1. 홈

순서: 히어로 카드 → [다음 일정 | 다음 기념일] 2열 → 공개 범위 필터 → 디데이 리스트

| 영역 | 커플 | 솔로 |
|---|---|---|
| 히어로 | 두 사람 사진, "○○ · ○○가 함께한 지 N일" | 대표로 고정한 디데이. 고정이 없으면 가장 가까운 다가오는 항목, 그것도 없으면 숨김 |
| 다음 일정 | 오늘 이후 가장 빠른 미완료 일정 1개 (같은 날이면 시각 순). 없으면 "일정 추가" | 같음 |
| 다음 기념일 | 다음 자동 기념일 + 진행 바 | 없음 (히어로가 대표 디데이의 다음 도래일을 이미 보여줌) |
| 필터 | 전체 / 우리 / 나만 | 없음 |
| 연결 유도 | 없음 | "커플 코드로 연결하기" 카드 (닫기 가능) |
| 리스트 | 디데이 + "디데이로 세기" 켠 일정. 다가오는 것(가까운 순) → 지난 것(최근 순), 히어로 항목은 뺌 | 같음 |

빈 상태: 일러스트, "첫 디데이를 등록해보세요", 빠른 시작 칩(생일 · 여행 · 시험 · 전역일), 추가 버튼.

- 헤더: 앱 이름 + 알림 버튼(알림 목록으로 이동)
- 빠른 시작 칩: 디데이 추가를 카테고리 · 제목을 채워서 연다 (생일 → 생일, 여행 → 여행, 시험 · 전역일 → 시험·목표)
- 추가 버튼: 디데이 추가로 바로 이동
- 커플 연결 카드: 빈 상태에서도 보이며, 닫으면 기기에 저장해 다시 보이지 않음
- 리스트 숫자: 7일 이내는 danger, 나머지는 text-primary. 반복 항목은 "매년 · 매월" 뱃지. 솔로에서는 모든 항목이 나만 보기라 공개 범위 뱃지를 붙이지 않음
- 항목을 누르면 디데이는 상세, 일정은 수정 화면 (4-5)

### 4-2. + 버튼

- 바텀시트로 [디데이 / 일정] 선택.
- 캘린더에서 날짜를 선택한 상태로 누르면 그 날짜를 미리 채워서 엽니다.

### 4-3. 캘린더

- 탭 이름은 "캘린더".
- 마커: 디데이 · 기념일은 primary 점, 일정은 accent 점. 일요일 · 토요일 색 구분.
- 날짜를 누르면 아래 리스트가 그날 항목으로 바뀌고, 선택하지 않았을 때는 이번 달 전체를 보여줍니다.
- 일정은 시간과 완료 체크박스를 함께 표시합니다.

### 4-4. 디데이 상세

- 상단: 배경 사진 1장 + 큰 D-day 숫자 + 기준일 · 계산 방식 · 공개 범위.
- 다가오는 기념일 타임라인: 지난 것은 흐리게, 다음 것 강조.
- 메모, "이미지로 공유", "위젯 추가".

### 4-5. 디데이 추가 · 수정

헤더: 취소 / 디데이 추가 / 저장

입력: 아이콘 + 제목, 카테고리, 날짜, 계산 방식(D-Day / D+), 시작일 1일 세기(D+일 때만), 반복, 알림(당일 · 1일 전 · 7일 전), 공개 범위(커플 연결 시), 색 · 배경 사진, 홈 대표로 고정.

| 항목 | 정한 내용 |
|---|---|
| 아이콘 | 8종: 하트 · 케이크 · 비행기 · 학사모 · 별 · 달력 · 선물 · 깃발. 카테고리를 고르면 맞는 아이콘을 미리 고르고, 직접 바꾼 뒤에는 유지 (`icon_key` = `ItemIcon` 이름) |
| 색 | 4종 = 테마 4종의 대표색 (핑크 · 네이비 · 세이지 · 라벤더). 화면이 다크면 그 테마의 다크 값 (`color_key` = `AppThemeType` 이름) |
| 알림 발송 시각 | 오전 9시 고정 |
| 일정 입력 | 날짜(선택, 지울 수 있음), 시간(종일 · 아침 · 점심 · 저녁 · 시간 지정), 장소(텍스트), 메모, 알림, 디데이로 세기. 카테고리 · 대표 고정은 디데이만 |
| 삭제 | 수정 화면 맨 아래 "삭제" → 확인 다이얼로그 |
| 일정을 눌렀을 때 | 상세 없이 바로 수정 화면 (상세 4-4는 디데이 전용) |
| 미루는 것 | 배경 사진은 이미지 저장소(Worker · R2)를 만드는 커플 모드 단계에서. 공개 범위 선택은 커플 연결 시에만 보이므로 솔로 단계에서는 숨김 |

## 5. 약관 동의 (온보딩)

로그인 직후, 시작 방식 선택 전.

| 항목 | 구분 |
|---|---|
| 전체 동의 | – |
| 만 14세 이상입니다 | 필수 |
| 서비스 이용약관 | 필수 |
| 개인정보 수집 · 이용 동의 | 필수 |
| 마케팅 정보 수신 | 선택 |

필수 항목을 모두 체크해야 "동의하고 시작하기"가 활성화됩니다. 마케팅 수신은 이후 알림 설정에서 변경합니다.

## 6. 설정 구조

```
설정 (탭)
├─ 프로필 카드 ─────────→ 프로필 수정 (이름, 사진, 생일)
├─ 커플
│   └─ 커플 관리 ───────→ 연결된 상대 · 사귄 날 · 1일로 세기 · [연결 해제]
│                         (솔로일 때는 "커플 코드로 연결하기")
├─ 앱 설정
│   ├─ 테마 ────────────→ 바텀시트 (4 테마 + 라이트 / 다크 / 시스템). 고르는 즉시 앱 전체에 미리보기,
│   │                     [테마 적용하기]로 저장, 적용하지 않고 닫으면 원래 테마로 되돌림
│   ├─ 알림 ────────────→ 기념일 · 일정 · 상대 활동 알림, 알림 시간, 마케팅 수신
│   └─ 위젯 ────────────→ 위젯 설정
├─ 지원
│   ├─ 공지사항
│   ├─ 문의하기
│   └─ 앱 평가하기
├─ 정보
│   └─ 약관 및 정책 ────→ 개인정보 처리방침 (굵게, 맨 위)
│                         서비스 이용약관
│                         오픈소스 라이선스 ──→ oss-licenses 플러그인 화면
├─ 계정 관리 ───────────→ 로그인 수단 · 로그아웃 · [회원 탈퇴]
└─ 앱 버전 (리스트 맨 아래 텍스트)
```

- 오픈소스 라이선스는 직접 화면을 만들지 않고 oss-licenses 플러그인이 만든 목록을 엽니다. 플러그인은 Gradle 의존성만 모으므로 **Pretendard 글꼴(SIL OFL) 고지는 따로 표시**합니다.
- 정책 문서는 한 단계 안쪽에 둡니다. 개인정보 처리방침은 그 목록 맨 위에 굵게 표시합니다.
- 회원 탈퇴 · 커플 연결 해제처럼 되돌리기 어려운 동작은 최상위가 아니라 하위 화면 맨 아래에 둡니다.
- 앱 안에서 회원 탈퇴가 가능해야 합니다.
- 백업 · 복원 메뉴는 두지 않습니다 (로그인 기반 동기화).
- 정책 문서는 Cloudflare Pages에 배포한 페이지를 웹뷰로 엽니다 (`infra-and-billing-protection.md`).

## 7. 커플 정책

| 항목 | 정책 |
|---|---|
| 코드 | 6자리 영문 대문자 + 숫자 (0/O, 1/I 제외), 24시간 유효 |
| 연결 시 기존 항목 | 자동 공유하지 않음. 항목별로 공개 범위 변경 |
| 사귄 날 | 한 명이 입력, 양쪽에 동일 적용, 이후 수정 가능 |
| 연결 해제 | 공유 항목은 각자에게 개인 사본으로 남음. "사본도 삭제" 선택 가능. 상대에게 알림 |
| 재연결 | 30일 이내 같은 상대와 재연결 시 기존 공유 데이터 복구 |
| 광고 제거 구매 | 한 명이 구매하면 두 사람 모두 적용 (`ads-strategy.md`) |

## 11. 디자인 시안 작업 (Stitch)

시안은 `docs/days/design/{화면}/`에 있습니다 (`screen.png`, `code.html`). 아래 항목은 시안에 들어 있지만 **이 문서와 다르므로 구현하지 않습니다.**

| 시안 | 기준 |
|---|---|
| 로그인의 Apple 로그인 | 카카오 · Google만 (Apple은 iOS 출시 때) |
| 탈퇴 · 커플 관리 · 캘린더의 사진 수 · 데이트 버킷 · 공유 앨범 · 데이트 장소 리스트 | 범위 밖 (10장) |
| 계정 관리의 Face ID 앱 잠금 | 범위에 없음 |
| 위젯 설정의 iOS 규격 문구 | Android, 중간 크기 4×2 (8장) |
| 정책 화면의 "AES-256 암호화" 등 보안 문구 | 실제 구현과 맞는 문구만 사용 |

| `_stitch-design-system/DESIGN.md`의 색 · 글꼴(Plus Jakarta Sans) | 색은 `theme-guide.md` 토큰, 글꼴은 Pretendard. 글자 크기 · 굵기 값만 사용 (`theme-guide.md` 9장) |

시안이 없는 화면: 프로필 수정.

설정 탭 시안(`design/settings/`)에서 문서와 다른 부분: "우리들의 공간 · 기록 보관함" 카드는 범위 밖이라 넣지 않고, 알림은 토글이 아니라 알림 설정 화면으로 이동하는 행으로 둡니다 (6장).

- 새 프로젝트에서 `theme-guide.md`(테마 가이드)를 디자인 시스템으로 넣고 시작합니다.
